## Decisions

- **Generator reuse (task 1.4) is reverted, and the plan's design decision 3 is wrong.** Sharing one
  `AVAssetImageGenerator` across batches broke rendering outright: 191 of 204 batches requested
  images and received **zero**, with zero decode failures — the stream just finished empty.
  `cancelAllCGImageGeneration()` is all-or-nothing per generator, so a stale batch's cancel poisons a
  newer batch's requests on the shared instance. The batch-ID guard cannot prevent this: at the
  moment the stale batch cancels, the newer batch has not yet called `render()`, so the stale token
  is still current and the cancel proceeds. Promoted to `decisions.md` §8.
- **Why it survived review:** `scheduleRender()` only sleeps 80 ms when `isScrolling || isMagnifying`.
  Scroll- and pinch-driven renders are debounced and appeared to work; the zoom **slider** and
  keyboard zoom are not debounced, call `render()` immediately, and broke. The user caught it —
  "zooming via slider does not trigger drawing of thumbnails" — after a clean build, strict
  concurrency, and a scroll-based smoke test had all passed it.
- **Completion bump must be gated on `pendingSinceBump`.** Cancelling a batch terminates the
  `AsyncStream`, so `for await` exits with **zero iterations** and the in-loop
  `if Task.isCancelled { return }` guard never runs. An unconditional post-loop bump therefore fired
  a whole-grid invalidation for every cancelled batch — 94 of them in one session of slider
  dragging, quietly eating a chunk of the win the throttle was meant to deliver.
- **Same-file tasks cannot be parallel subagents.** Split waves by write target.

## Findings logged, not yet acted on

- **Continuous `density` defeats the thumbnail cache.** `density = pow(2, zoomLevel × 0.6)` is
  continuous and frame times are `i / density`, so every slider or pinch zoom position mints an
  entirely fresh set of `timeMillis` cache keys — a near-100% miss rate across zooms. Width is
  already bucketed to 60/120/240; density is not. Quantising density to a ladder would let nearby
  zoom levels share decoded frames. Keyboard zoom (`zoomStep = 0.5`) already lands on repeatable
  densities and does hit cache.
- **Slow redraw when zooming back out to 1.0** (user-reported). Two candidate causes, untested, with
  opposite fixes: **(A) eviction** — `ThumbnailCache` is one 500 MB `NSCache` shared across all
  buckets, and bucket-240 images (~518 KB) are ~16× bucket-60 (~32 KB), so a zoomed-in session
  evicts the whole zoomed-out strip; **(B) never cached** — zoom 1.0 spans far more timeline than
  was ever decoded. Settle it by tracking every stored `ThumbKey` and checking whether misses land
  on previously-stored keys.
