## Goal
Find performance improvements for thumbnail-strip + player navigation (user: app is

## Progress
- **User smoke-confirmed yesterday's transport work**: J/K/L shuttle and ⌥/⇧ arrow jumps all work.
- **3-agent performance investigation (Sonnet, per user request)** — code audit of the `Thumbnail/`
  subsystem, AVFoundation research (Apple docs MCPs + web), SwiftUI rendering research. The two
  code-facing agents independently converged on the same top findings; Sonnet quality was sufficient.
- **Every finding re-verified against source before reporting** (read all 5 Thumbnail files). Verified
  root causes, ranked:
  1. **HIGH** — whole strip body re-evals at 30 Hz during playback (`currentTime` `@State`,
     `ThumbnailStripView.swift:481`); each pass rebuilds the unmemoized full-clip `times` array 3×
     (`:45,192-193,458-467`; `StripModel.swift:70-82`); scroll-geometry transform rebuilds it again
     per scroll tick just for `.count` (`:334`).
  2. **HIGH** — `cacheVersion &+= 1` per streamed image (`StripModel.swift:197`) → up to 256
     full-grid invalidations per batch, amplified by per-cell `.onChange(of: cacheVersion)`
     (`ThumbnailCellView.swift:59`) into ~visibleCells×images redundant cache lookups.
  3. **MED-HIGH** — all navigation seeks are `.zero`-tolerance fire-and-forget with no coalescing
     (`ThumbnailStripView.swift:177-181,201-205,454`); key auto-repeat stacks max-cost seeks
     (Apple QA1820 pattern is the fix).
  4. **MED** — fresh `AVAssetImageGenerator` per render batch (`ThumbnailRenderer.swift:31`).
  5. **LOW-MED** — thumbnail tolerance flips to `.zero` at density ≥ 5 (`StripModel.swift:95-97`),
     against WWDC22 #110379 guidance.
  6. **LOW** — per-cell `onModifierKeysChanged`, `Array(times.enumerated())` alloc, string `cellIdentity`.
- **Confirmed already-correct** (agents + my verification): `maximumSize` set (2× bucket), decode
  off-MainActor, `Image(decorative: CGImage)`, 256 cap + center priority, viewport-scoped prefetch,
  `cancelAllCGImageGeneration()` on cancel, both debounces, NSCache cost accounting. Ruled out
  `AVSampleBufferGenerator` / `AVPlayerVideoOutput` (scope mismatch).
- **Corrected one agent claim during verification**: "keyboard nav bypasses the 80 ms debounce" is
  unconfirmed — animated `scrollTo` likely reports the `.animating` scroll phase which sets
  `isScrolling`. Plan settles it empirically (Wave 3.2) before writing code.
- **Wrote `IMPLEMENTATION_PLAN.md`** (repo root, the filename `/execute` expects) via `/make-plan`:
  15 tasks, 5 waves — 0 CPU baseline → 1 model/renderer (memoized index-based times, throttled
  cacheVersion, half-gap tolerance, generator reuse) → 2 view restructuring (no raw-time `@State`,
  transport-bar + border leaf views, cell `Equatable`) → 3 seek coalescing → 4 smoke matrix +
  before/after CPU. Load-bearing traps documented in the plan's "design decisions" section:
  generator-reuse cancellation race (batch-ID guard), `@State` invalidation is declaration-scoped,
  cell `==` must include `cacheVersion` or images stop refreshing, border-offset math must reuse the
  arrow-nav `cellsPerRow` formula, do NOT loosen navigation-seek tolerance (border off-by-one risk).
