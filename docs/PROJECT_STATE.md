# PROJECT_STATE — ScreenshotFromVideos

*Last updated: 2026-07-18 — slimmed to the lean digest. Full narrative lives in `sessions/`, rationale in `decisions.md`.*

## Identity
macOS app that extracts still frames from a video as PNGs — every Nth frame or hand-picked timestamps — with optional timestamp burn-in and chronological filename numbering. Built to feed Claude Code visual context from screen recordings. Also exports JPG / HEIC / WebP.

- **User-facing name:** "Stills From Video" (since 2026-05-27). Internal IDs stay `ScreenshotFromVideos` (bundle `com.lucesumbrarum.ScreenshotFromVideos`, team `FDMSRXXN73`).
- **Design target:** short clips, 30 s–2 min. Longer clips work but the strip renders slower; multi-hour optimization is explicitly out of scope.
- **Packages:** adopt MediaKit + FolderAccessKit · source for MediaKit + ImageIOKit — see `docs/PACKAGE-NOTES.md`.

## Now
- **Phase:** performance pass on the thumbnail strip + player.
- **Focus:** cutting strip/player CPU via a 5-wave plan (`IMPLEMENTATION_PLAN.md`) — Wave 0 baseline measured 2026-07-10; Wave 1 closed 2026-07-19; Wave 2 (view restructuring) is next and carries the two biggest wins.
- **Blockers:** none.
- **Next:** `/execute` → Wave 2 (rework time observation, extract transport bar + border overlay, cell cleanup). Wave 2.1 also fixes the auto-follow-during-playback bug.

## Recent
- **2026-07-19** — Wave 1 (model + renderer) closed. Thumbnail times are now generated by index and memoized instead of rebuilt by an accumulating loop on every view pass; the grid-refresh signal is throttled from up to 256 whole-grid invalidations per batch down to ~10/s; thumbnail decode tolerance loosened to half the gap between frames. Zoom now feels snappy. One planned change was **reverted**: sharing a single frame-generator across batches broke thumbnail drawing entirely on the zoom-slider path, and the plan's design note for it is wrong — recorded so nobody retries it blind. Playback CPU is unchanged, as expected; that's Wave 2's target. Two new findings logged: nearly every zoom position generates fresh cache keys (so almost nothing is reused across zooms), and zooming back out redraws slowly for a reason not yet pinned down.
- **2026-07-10** — Investigated why strip/player navigation feels slow, wrote the 5-wave fix plan, then measured a live CPU baseline on a 30-min stress clip (plain playback ~92%, shuttling ~105%, zoom bursts to ~188%). Found a real bug along the way: the strip stops auto-scrolling during ordinary playback, so the highlighted frame walks off-screen — fix folded into Wave 2.
- **2026-07-09** — Got the app building + running on this Mac (rebuilt the Syncthing-stripped git repo from GitHub, ad-hoc signed). Shipped playback transport: J/K/L shuttle, Space/K play-pause, ⌥/⇧ arrow jumps, plus a debounce that fixed scrub jitter.
- **2026-06-12** — Live UI polish from the running app: working zoom buttons, arrow-key strip nav, always-visible transport bar, timestamp burn-in fixed (was a font-size bug), Show-in-Finder, filename time-tokens, Q/⌘C capture-vs-copy. Merged the whole stack to `main` and pushed to a new public GitHub repo. Added a README + Sparkle "Check for Updates" + a release kit.
- **2026-05-29** — Added WebP export via a third-party encoder (macOS's ImageIO can't write WebP). Quality/effort slider + lossless toggle; 4K smoke passed (lossless turned out near-lossless, not bit-exact — accepted, tooltip corrected).
- **2026-05-28** — Closed the thumbnail-strip phase. Shipped frame-count preview, multi-format export (PNG/JPG/HEIC), and a clearer Unload button. Fixed a CPU-saturation bug from fast pinch on a long clip.
